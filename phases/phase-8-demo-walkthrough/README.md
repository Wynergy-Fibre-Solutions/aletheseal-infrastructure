\# Phase 8 — Demo Walkthrough Outline



Objective:

Provide a clear, repeatable demonstration of Aletheseal that converts interest into purchase.



Audience:

\- Journalists

\- Publishers

\- Investigative platforms

\- Decision-makers with low technical tolerance



Duration:

10–15 minutes.



---



\## Demo Structure



\### 1. Context (1 minute)

Explain the problem:

\- Credibility is attacked through technical vectors.

\- Email failures, domain mistrust, silent blocking.

\- Most platforms never see the attack coming.



Position Aletheseal as prevention, not reaction.



---



\### 2. Live Proof (3 minutes)

Show runtime verification:

\- Perform a HEAD request against the live domain.

\- Point out:

&nbsp; - X-Content-Type-Options

&nbsp; - X-Frame-Options

&nbsp; - Referrer-Policy

&nbsp; - CSP presence



Emphasise: this is observable, not claimed.



---



\### 3. Infrastructure Evidence (4 minutes)

Open this repository:

\- Walk through Phase 4 (Web Trust)

\- Show DNS, SPF, DKIM, DMARC evidence

\- Explain that each phase is documented and auditable



Key point:

This is not configuration. It is evidence.



---



\### 4. Commercial Mapping (3 minutes)

Show Phase 5 and Phase 6:

\- Explain how phases map directly to pricing tiers

\- Make clear what the buyer gets at each level

\- Highlight simplicity and transparency



---



\### 5. Close (2 minutes)

Reinforce:

\- Aletheseal is not content.

\- It is trust infrastructure.

\- It can be deployed, demonstrated, and transferred.



End with:

“Would you like Core Trust or Pro Trust?”



---



\## Demo Assets

\- This GitHub repository

\- Phase documentation



Outcome:

A confident, evidence-led close without pressure.
